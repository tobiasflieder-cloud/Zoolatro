- **Immer auf Deutsch antworten.** Kurz, freundlich, sachlich.
- **Feedback von Tobi:** aufnehmen, Ursache klären (bei Bedarf im Code nachsehen), Lösung vorschlagen, dann
  am Ende **„Liste fürs nächste Bauen“** (nummeriert) und **„Für später“** zeigen.
- **Nur bauen, wenn Tobi es ausdrücklich sagt** („Bauen bitte“, „Bau um“, „Bau das schon mal“ …).

  dann nur Vorschlag bzw. Liste zeigen und auf „Bauen bitte“ warten. Bei Unklarheit nachfragen.

  1. Version in `const VERSION` hochzählen. **Neues Schema ab der Version nach 0.96 (Tobi 26.10.): 0.51a, dann 0.52a, 0.53a …** (Zahl steigt, „a“ bleibt). ## 2. Einrichtung in einer neuen Sitzung

```
mkdir -p /home/claude && cd /home/claude
# Paket entpacken, dann:
cp spiel/zoodeck.html /home/claude/zoodeck.html
npm install jsdom playwright-core      # für Tests/Screenshots (Chromium: /opt/pw-browsers/chromium)
pip install openpyxl --break-system-packages   # für die Excel-Liste
```
Die Werkzeuge erwarten die Spieldatei unter `/home/claude/zoodeck.html` (oder Umgebungsvariable `ZF=pfad`)
und werden **aus dem Ordner `werkzeuge/` heraus** gestartet (sie laden z. B. `bot7.js` relativ).

## 3. Pakete bauen

Die beiden ZIPs in `pakete/` entpacken nach `/home/claude/zoolatro-github` und `/home/claude/zoolatro-app`.
- `zoolatro-github/index.html` und `zoolatro-app/www/index.html` enthalten die komplette Spieldatei eingebettet:
  den alten Spielinhalt (Sicherung der Vorversion) per exaktem Textersatz durch den neuen ersetzen (muss genau 1× vorkommen).
- `zoolatro-github/sw.js`: Cache-Name `zoolatro-vXX` hochzählen.
- Quelltext neu zerlegen: `python3 zoolatro-github/quelltext/split.py zoodeck.html`;
  Kontrolle: `python3 zoolatro-github/quelltext/build.py /tmp/rt.html && cmp zoodeck.html /tmp/rt.html`.
- Zippen: `(cd zoolatro-github && zip -qr ../Zoolatro-GitHub-0.xx.zip .)`, ebenso App; alte ZIPs löschen.
- Excel: `node dump2.js` (schreibt `alldata.json`), Versionsnummer in `mkxl.py` anpassen, `python3 mkxl.py`
  (speichert nach `/home/claude/out/`).

05 Ton · 06 Spiel · 07 Anzeige · 08 Shop/Menüs · 09 Speichern/Lauf · 10 Tutorial · 11 Bildschirme.

- **Karten:** `CARDS` (Werte, Form, `bonus`-Funktion), Texte in `TXT.de.card`. Eigenschaften in `TRAITS`
  (raubtier/beute/scheu/show), dazu `tags` (bedroht, gross, einmalig). Lebensraum-Bindung über `rq`.
- **Wertung:** `evalB(b,bs,idx,parts)` → feste Boni, dann Prozent-Boni (Förderprogramme, Werbung, Spezialisten,
  Gold, Futterküche/Lotse) alle auf denselben Grundwert `pa0/ps0`, dann Profil/Veredelungen/Felder/Star/Scheinwerfer,
  **ganz am Ende Show** (`STRESS=.3`, max. 2 Auslöser; Bühne verdoppelt), danach TÜV-Halbierung. **Stress (ab 0.64) zoo-weit, ab 0.65 im Umkreis von 2 Feldern (`nbrs2`):** evalB liefert `st` (Störer, max. 2 je Tier; Tierarzt muss direkt daneben stehen), `scoreZoo0` macht daraus den Multiplikator 😣 −5 % Natur je Störer (`STRZ`, max. −40 % `STRMAX`).
  Jagdrevier/Partyzoo bleiben lokal +30 %. Kopien von Karten mit `derive(p,o)` (nicht `Object.assign(Object.create…)`, weil Jungtiere Getter haben).
  `scoreZoo` → Multiplikatoren (Kronenfeld `CROWNF=1.3`, Reinheit `PURN=5`, Stiftung …).
- **Winter-Bedingungen:** `INSP` (fx liefert `f` = Faktor B+N, `fs` = nur Natur, `a` = feste B). Immer über `inspFx()` abfragen (Regelbrecher Winterfest).
- **Wirtschaft:** `ENTRY=9` (1 Taler je 9 B, gestuft), Pflege 1 Taler je 8 N.
- **Ziele:** `ZLSEAS=[1.35,1.35,1.55,1.45]` (Wachstum je Zoo), Tutorial `TUTT=[15000,105000,360000,450000]`.
- **Lebensräume:** 6 (`HAB`), Lauf wählt 4 (`habsNow()`); Charakter `HABCHAR`.
- **Verstärker** (`cat:'verst'`, einmalig, Eigenwert 0): Futterküche +30 % N, Besucherlotse +30 % B, Scheinwerfer ×1,5
  stärkstes Gehege, Winterquartier (ohne Winter-Bedingung/Frost), Bühne, Ruhezone. Freischalten `VCOND` /
  `verstUnlock` (am Ende geschaffter Zoos) + Arktis-Zähler `cu.arB` in `tallyUnlock`. Gespeichert pro Spielstand in
  `sl.vu`. Test-Schalter `META.testVerst` (Titelbildschirm + Spielmenü), Testläufe mit 🧪 in Highscores.
- **Tutorial** (`TUT.zl/zlsh/zls/zlssh/zlh/zlhsh/zlw`, Kapitelstart `TUTCH`/`tutChapter`): Frühling/Sommer/Herbst
  komplett geführt, Winter allein. Ab Frühlingstag 4 bestimmt `tPlan()` die festen Felder zu Beginn jedes Schritts.
  Schritte bauen mit `tBld(key,text,hinweis,{day,pref,bp})`.

  Stufen `STAGES` (wirken in `initZl`, `priced`, `seTarget`/`stTF`, `rdFree`, `startDay`), Freischalten in `z2After()` (Zoo 3 geschafft → nächste Stufe).
